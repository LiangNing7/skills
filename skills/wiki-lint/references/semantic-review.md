# 语义巡检

程序输出提供定位线索，不自动证明页面需要加深、某命题过时或某术语需要建页。

## 判断维度

| 维度 | 阅读与判断依据 |
| --- | --- |
| 内容深度 | 按页面用途评估。术语定义页可以简短；实践／分析页应支持其目标，重要方法需有前提、来源和适用边界。 |
| 交叉引用 | 阅读链接两端；确认关系是定义、前提、对比、支持、限制或待验证联系。避免为密度增加无关链接。 |
| 命题矛盾 | 对齐对象、定义、硬件、软件版本、时间、负载及实验条件。先区分条件不同、弱分歧、强对立和根本性否定。 |
| 时效 | 日期／版本只提示核查；新资料不能自动胜出。软件行为以所用版本的源码／官方文档／实际验证为依据，历史实验保留原条件。 |
| 知识缺口 | 说明当前任务缺少哪项概念或证据、它影响什么判断，以及应该补什么材料／验证。频次与图谱密度不能代替这个解释。 |
| 概念与概览 | 对照概念表定义、证据状态、适用条件与正文；重要新来源是否已经影响研究概览和关联页。 |

## 输出

每项保留页面／原件定位、具体命题、双方条件、依据、严重程度、确定程度和建议。矛盾强度与修复严重程度分开记录。需要回查但尚未阅读的来源明确标为未核验。

报告分别说明程序覆盖和实际语义阅读范围；可列出已核查问题与未核查范围。不得将“未发现”改写为“全库没有矛盾”。

修复后的影响记录包括：修改依据、已更新页面、概念表／概览评估及仍待核实项。无法确认的新方案保留 proposed；不通过巡检写入 Memory。
